# Council Playbook

Read this reference only when the orchestrator has determined that multiple council perspectives are needed to resolve material creative tensions.

## Run upstream workflow skills before debate when needed

Council members should debate the strongest available evidence.

For example:

```txt
weak:
"Should this furniture website be minimalist or brutalist?"

stronger:
graphic-universe-builder
→ identifies joinery, modular forms, material texture, workshop documentation
→ council debates which source best supports the business and audience
```

Likewise:

```txt
weak:
"Which homepage do we like?"

stronger:
story-led-website-concept
→ provides three different narrative concepts
→ council compares their strategic consequences
```

Use structured workflow artifacts to improve the quality of disagreement.

---

## Run the council

### 1. Establish decision criteria

Label criteria:

* `critical`
* `important`
* `supporting`

Prefer criteria such as:

* strategic fit
* audience comprehension
* primary-action support
* evidence strength
* brand ownership
* accessibility
* responsive resilience
* production feasibility
* maintainability

Avoid arbitrary weighting unless numerical comparison is explicitly useful.

---

### 2. Run independent first positions

Give every selected perspective the same:

* problem frame
* evidence
* constraints
* candidate material

Require each to return:

```txt
Recommendation:
Strongest reason:
Non-negotiable:
Challenged assumption:
Primary risk:
Acceptable compromise:
```

Do not expose other positions first.

This reduces premature consensus.

---

### 3. Normalize the positions

Convert specialist responses into:

| Perspective | Proposal | Evidence | Value | Requirement | Risk | Cost | Conflict | Fallback |
| ----------- | -------- | -------- | ----- | ----------- | ---- | ---- | -------- | -------- |

Remove repetition.

Preserve meaningful disagreement.

---

### 4. Build the conflict map

Identify the most important conflicts.

Examples:

```txt
editorial pacing
vs
conversion speed
```

```txt
experimental interaction
vs
accessible baseline
```

```txt
visual richness
vs
system restraint
```

Cross-examine only the two most material conflicts per perspective.

Require:

```txt
Specific consequence:
Evidence:
Possible resolution:
What is sacrificed:
```

Do not debate low-impact preferences endlessly.

---

### 5. Identify shared non-negotiables

Admit a non-negotiable only when it protects:

* user objective
* core message
* primary action
* brand recognition
* accessibility
* truthfulness
* legal requirements
* technical viability

Do not treat stylistic preferences as non-negotiables.

---

## Candidate directions

### 6. Generate no more than three

When candidate generation is still required, produce:

#### Recommended direction

The strongest overall strategy.

#### Credible alternative

A meaningfully different option with legitimate advantages.

#### Experimental wildcard

Include only when:

* the project can tolerate risk
* it explores a genuinely different premise
* the potential upside is meaningful

Do not produce a wildcard simply for entertainment.

---

### 7. Keep candidates internally coherent

Do not accumulate every specialist recommendation into one direction.

Each candidate must have:

```txt
one central premise
one dominant narrative
one visual logic
one interaction character
one conversion strategy
```

Supporting elements may vary.

The result should not feel like a committee compromise.

---

## Direction decision

### 8. Compare candidates

Use:

```txt
strong
acceptable
weak
unverified
```

Compare:

| Criterion                | Direction A | Direction B | Direction C |
| ------------------------ | ----------- | ----------- | ----------- |
| Strategic fit            |             |             |             |
| Audience clarity         |             |             |             |
| Brand distinction        |             |             |             |
| Narrative strength       |             |             |             |
| Primary-action support   |             |             |             |
| Accessibility resilience |             |             |             |
| Responsive resilience    |             |             |             |
| Production feasibility   |             |             |             |
| Maintainability          |             |             |             |

Avoid fake mathematical precision.

---

### 9. Select one dominant direction

State explicitly:

```txt
Selected direction:

Preserves:
-

Sacrifices:
-

Rejects:
-

Requires validation:
-
```

A decision artifact should make trade-offs visible.

---

## Conflict-resolution hierarchy

When perspectives cannot be reconciled, resolve them in this order:

1. User objective and fixed constraints.
2. Truthfulness, legality, accessibility, and user autonomy.
3. Core content and primary action.
4. Comprehension and trust.
5. Brand meaning and distinction.
6. Responsive resilience.
7. Technical feasibility and maintainability.
8. Motion, interaction novelty, and polish.

A lower-priority concern may override a higher one only when strong evidence supports the trade-off.
